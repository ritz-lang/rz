# Ritzlib

The standard library for the Ritz programming language - system calls, I/O, collections, async I/O, and more.

**Part of the [Ritz Ecosystem](../docs/ECOSYSTEM.md)**

## Overview

Ritzlib is the standard library that ships with the Ritz compiler. It provides the foundational modules that Ritz programs need to interact with the operating system and work with data. Ritzlib is written in Ritz itself, making it both a practical library and a showcase of the language's capabilities.

The library is organized as individual `.ritz` files, each providing a focused set of functionality. Programs import specific modules they need rather than pulling in a monolithic standard library. Ritzlib is found automatically by the Ritz compiler via the `RITZ_PATH` environment variable.

Ritzlib spans from low-level syscall wrappers to high-level abstractions like async I/O with io_uring, JSON parsing, and hash maps. It targets Linux userspace and Harland userspace programs; the Harland kernel does not link it, and imports only `ritzlib.option`. Syscall numbers live only in `sys.ritz`, each under a `[[target_os]]`; `memory` gets its pages from a pluggable `PageSource` so a host without mmap can supply them.

Ritzlib's **core** (`str`, `strview`, `span`, `option`, `result`, `gvec`, `string`, `hashmap`, `memory`, `fmt`, `drop`, `hash`) builds freestanding: it imports nothing outside the core, so never `ritzlib.sys`, and reaches the platform only through three `extern fn ritz_platform_*` hooks that `sys` (or, weakly, every hosted `_start`) defines and a kernel defines for itself. The rest is **hosted**. `tools/ritzlib_layers.py` holds the list and fails when a core module imports a hosted one (docs/STDLIB_REFERENCE.md, "Core and hosted").

## Features

- System call wrappers for Linux and Harland targets
- String and string view operations
- Dynamic arrays (`gvec`) and hash maps
- Memory allocation and management
- File system operations
- Async I/O using Linux io_uring
- Network socket operations
- JSON parsing and serialization
- ELF binary parsing (used by ritzunit for test discovery)
- Process management and environment access
- Option and Result types for error handling
- Timer and async task primitives

## Usage

```ritz
import ritzlib.io

pub fn main() -> i32
    println("Hello, world!")
    0
```

```ritz
import ritzlib.fmt
import ritzlib.strview
import ritzlib.gvec

pub fn main() -> i32
    # A string literal is a StrView: a { ptr, len } pair, no allocation
    let s: StrView = "hello"
    let n: i64 = strview_len(s)
    print("{n}")

    # Vec<T> is the generic dynamic array
    var items: Vec<i64> = vec_new<i64>()
    items.push(42)
    let first: i64 = items.get(0)
    print("{first}")
    0                       # `items` is freed here (Vec has Drop)
```

## Dependencies

- Ritz compiler (ritzlib is part of the compiler distribution)
- Linux kernel 5.1+ for io_uring features

## Status

**Active development** - Core modules (sys, io, str, memory, gvec, hashmap) are stable and used by the full ecosystem. Async I/O, JSON, and collections are actively evolving alongside the compiler and ecosystem projects.
